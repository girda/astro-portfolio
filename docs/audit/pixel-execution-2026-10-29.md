# Pixel: проверка при отправке

## Изменения
Turnstile использует execution=execute и appearance=execute. Открытие панели загружает SDK и создаёт виджет, но не запускает challenge. Каждая отправка сбрасывает предыдущий токен, устанавливает ожидание и вызывает reset + execute. Автоматический reset SDK из finally удалён: повторная проверка нужна при следующей отправке. Исключение SDK переводит запрос в существующее состояние ошибки и освобождает форму. При ширине контейнера менее 300 px используется компактный виджет. В лог попадает только публичный шестизначный код ошибки, без токена и текста диалога.

Siteverify на сервере, ключи, разрешённые hostname, лимиты и Worker не менялись. Проверка не обходится.

## Проверки
- npm test: 56/56, включая новый токен после отказа и восстановление после исключения SDK.
- npm run build: успешно; повторная сборка с публичным PUBLIC_ASSISTANT_API_URL успешна.
- npm run check:seo: PASS; git diff --check: PASS.
- Playwright, production build, 320×740, локальные fixtures SDK/API: при открытии execution=execute, compact, 0 запусков; две отправки — 2 POST с различными тестовыми токенами; исключение reset — число POST остаётся 2, ссылка контактов доступна; повтор — третий POST с новым токеном. В конце aria-busy снят. Это проверка клиентской логики, не настоящий ответ модели и не успешный проход Cloudflare.

## Ограничения
Сообщения CSP data:, присланы из фрейма Cloudflare; их причинная связь с отказом не установлена. CSP сайта вслепую не менялась. Публичный проход настоящей проверки и ответ модели после публикации ещё не подтверждены. Для диагностики оставшейся ошибки нужен код [Pixel] Turnstile из обычного браузера; токены не нужны.

Документация: https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/widget-configurations/ и https://developers.cloudflare.com/turnstile/troubleshooting/client-side-errors/ .
