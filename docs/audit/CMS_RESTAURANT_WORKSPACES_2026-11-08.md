# My Menu — этап 1: пространства ресторанов

Дата: 2026-11-08. Локальная CMS: http://127.0.0.1:8790/. Облачный Worker не опубликован, удалённые D1/Access/DNS не изменены.

## Реализовано

- `restaurants`, `restaurant_memberships`, `restaurant_catalogues`, `restaurant_history` — [миграция 0003](../../apps/menu-cms/cloud/migrations/0003-restaurants.sql).
- У каждого ресторана свой snapshot, настройки, история и ревизия. Новый каталог пустой: чужие блюда и контакты не копируются.
- Серверные роли owner/editor/viewer в ресторане; platform super-admin сохраняет общий административный доступ. Старый глобальный editor не получает доступ ко всем ресторанам. Удалена прежняя глобальная функция `canWrite`, чтобы не использовать её вместо членства.
- Общая обработка scoped API для D1 и локальной SQLite: [catalogue-api](../../apps/menu-cms/catalogue-api.mjs), [restaurants](../../apps/menu-cms/restaurants.mjs), [store](../../apps/menu-cms/cloud/store.mjs). API получает пользователя от серверной проверки identity, а не из JSON запроса.
- Список доступных ресторанов, создание, выбор в существующей шапке CMS. Несохранённые правки требуют подтверждения перед переключением/созданием. Диалог закрывается Escape, кроме запроса в процессе сохранения.
- По решению пользователя новые подтверждённые email получают active/viewer без ручного одобрения; создание ресторана требует имени. Это не выдаёт членство в существующих ресторанах. Старые pending/blocked сохраняются.
- Предпросмотр привязан к ресторану через `?restaurant=ID`, права проверяются сервером. Облако не принимает старые нескопированные API; локальные `/api/catalogue` и аналоги оставлены только как совместимые aliases внутреннего демо в loopback-режиме.
- Исходные таблицы сохранены как снимок, содержимое перенесено в `internal-demo`. Перед первой локальной миграцией создаётся `menu.sqlite.pre-restaurants-TIMESTAMP.sqlite` с правами 0600 в игнорируемой `.local-data`.
- Первичный экспорт теперь включает все ресторанные пространства, пользователей, настройки и историю. Файл приватный 0600; повторный импорт в уже мигрированную БД останавливается. Это **не** инструмент слияния с существующим production.

## Проверки

- **Пройдено:** `npm test` — 103/103, включая 6 новых сценариев tenant-изоляции/миграции/экспорта. Тесты выполняются на отдельных временных SQLite-базах; это проверка доменной логики и SQL, не живой Cloudflare E2E.
- **Пройдено:** A не читает/не изменяет B; чужие resource/category IDs отклоняются; история и settings изолированы; ревизии независимы; viewer не пишет; blocked/pending не создают ресторан; global editor не обходит membership; platform super сохраняет доступ.
- **Пройдено:** миграция старого каталога и settings, сохранение history, повторный локальный запуск без reseed, первичный export/import round-trip, отказ повторного импорта.
- **Пройдено:** фактическая локальная база на 8790 сравнена с pre-migration backup: категории, блюда, settings, ревизия и количество событий совпадают.
- **Пройдено:** общая сборка, check:public, check:seo, check:legal, check:media; это технические проверки, не юридическое заключение.
- **Пройдено:** Cloud assets build и Wrangler dry-run. Публикация не выполнялась.
- **Пройдено в Playwright:** создание A/B на временной базе 8792, пустой новый каталог, категория A не попадает в B, переключение, подтверждение несохранённых settings и Escape, все три preview пустого ресторана без JS-ошибок; smoke основной CMS 8790 без JS-ошибок.
- **Пройдено в эмуляции:** 320×740, 390×844, 768×1024, 1024×768, 1920×1080, 2560×1440, 3840×2160. Новая шапка и create-dialog без горизонтального переполнения; диалог помещается в viewport. Скриншоты: [телефон](assets/cms-workspaces-mobile.png), [desktop](assets/cms-workspaces-desktop.png).
- **Не проверено:** физический телефон/4K-монитор, внешняя email-регистрация и миграция удалённой D1. Локальная CMS остаётся режимом разработки без персонального входа; серверный ACL проверен на отдельных пользователях в тестах.

## Как проверить локально

Открыть 8790, выбрать внутреннее демо либо «Restaurant erstellen». Новый ресторан начинает с пустого каталога. Добавить категорию/блюдо, переключиться обратно: данные не смешиваются. Для просмотра конкретного черновика использовать ссылки из вкладки Vorschau. Новый slug пока резервируется в БД, но не создаёт настоящий поддомен.

## Следующий этап / ограничения

Постоянный URL, публичное меню, publish/rollback и серверный выбор темы ещё не реализованы в этом коммите. Следующий этап готовится локально: домена пока нет. Ресторанный выбор здесь относится к черновикам. Загрузка фото, приглашение сотрудников, billing/trial и изменение контактов входят в последующие этапы.

Перед будущим Cloudflare deploy нужны резервная копия удалённой D1 и применение 0003 к существующей схеме до переключения Worker. Не импортировать локальный SQL поверх действующей базы; не открывать draft preview гостям. Согласование серверной публикации остаётся отдельным действием.
