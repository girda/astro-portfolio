# Pixel — карточка подтверждения заявки

Дата: 24.10.2026. Статус: **локальный Publish применён по подтверждению Артёма**. Версия `Pixel — bestätigte Anfrage 2026-10-24`; n8n показывает Published. Связь Save Lead с AI Agent отключена в активной версии. Карточка и сохранение проверены; GitHub Pages не менялся.

## Что изменено

- В существующем Pixel добавлена карточка с именем, email/WhatsApp, текстом проекта и необязательным бюджетом. Оформление чата, эмоции, адаптивность и прежний публичный API сохранены.
- «Anfrage vorbereiten» открывает карточку без нового запроса к модели. Предзаполнение — только дословные сообщения посетителя текущей консультации. При превышении 1500 знаков поле оставляется пустым для ручного заполнения; текст не обрезается молча. Ответы модели не используются как подтверждённые факты.
- Причина этого решения: реальная модель в черновике однажды добавила неуказанные бюджет и срок. Prompt сам по себе не гарантирует точность извлечения. Имя/контакт/бюджет не достраиваются моделью.
- Два действия: проверить поля → явно сохранить заявку. Сначала backend хранит только хеш полей, идентификаторы и токен черновика, без текста имени/контакта/проекта. После подтверждения сохраняет согласованные поля в leads.
- Отдельный Node-сервис на loopback 127.0.0.1:8788; SQLite из node:sqlite, новых npm-зависимостей нет. База `apps/assistant-api/.local-data/pixel-leads.sqlite`, каталог 0700, файл 0600, каталог игнорируется Git.
- Транзакция и UNIQUE(draft_id) дают одну запись на подтверждаемый черновик. Повтор после неизвестного результата возвращает тот же id. Отдельно созданный и подтверждённый черновик считается отдельной заявкой; глобальное сравнение по имени/контакту не выполняется.
- Проверяются scope=consult, UUID сессии/операции, типы/размеры/контакт/описание, точное совпадение подтверждаемых полей, токен и срок 15 минут. Повтор уже сохранённой операции возвращает успех даже после истечения срока.
- JSON/Origin/Host/размер тела/частота запросов проверяются сервером. Это локальный сервис, не готовый публичный endpoint: CORS не является аутентификацией, scope и UUID не доказывают физическое нажатие человеком. До внешней публикации нужны отдельные меры против злоупотребления и решение о хранении персональных данных.
- В применённой локальной версии n8n отключена связь Call HIRDA — Save Lead → AI Agent; узел, отдельный workflow, таблица и старые строки не удалены. System Message направляет к карточке и не обещает сохранение из одного текстового сообщения.
- GitHub Pages не опубликован и к loopback-сервису не подключён. `.env.local` не коммитился.

В постоянной новой SQLite оставлены три синтетические QA-заявки id=1, id=2 и id=3. Ничего не отправлялось клиентам. Старые строки HIRDA Leads в n8n не менялись. Два ожидаемых browser network errors относятся к намеренно оборванному ответу и HTTP 400 для неверного контакта; это тесты ошибок, а не доказательство отсутствия любых console errors.

## Проверка после Publish

Активный чат localhost:4321: на просьбу сохранить без подтверждения получен HTTP 200; Pixel направил к карточке и не заявил об успешной записи. До подтверждения в SQLite оставалось 2 строки, в том числе после проверки полей. Только кнопка «Anfrage speichern» создала id=3, status=new, и число строк выросло до 3. В прежней таблице HIRDA Leads по-прежнему Total 2, новых строк там нет. Фокус после Enter сохранён. Тестовые контакты синтетические, уведомления не отправлялись.

Доказательства: `pixel-workflow/lead-stage/n8n-published.png` и `applied-card-proof.png`. Код на этапе активации не менялся; прежние 28 тестов и сборка остаются проверкой реализации, активный webhook проверен отдельно.

## Запуск и файлы

1. В `apps/assistant-api`: `npm run leads` (сервер уже запущен в текущей локальной сессии).
2. В `apps/portfolio/.env.local`: `PUBLIC_PIXEL_LEADS_URL=http://127.0.0.1:8788/api/leads`, рядом существующий PUBLIC_N8N_CHAT_URL. Не копировать секреты в PUBLIC_.
3. Astro: использовать существующий localhost:4321; при ручном запуске `npm run dev -- --background --port 4321`.
4. Чат → описать реальный проект → «Anfrage vorbereiten» → заполнить/исправить → «Angaben prüfen» → «Anfrage speichern».

Код: `apps/portfolio/src/scripts/pixel-lead.ts`, `src/styles/pixel-lead.css`, `src/data/lead-contract.mjs`, существующие `AIAssistantWidget.astro` и `pixel-n8n.ts`; backend `apps/assistant-api/lead-{server,http,store}.mjs`; тесты `lead.test.mjs` и `apps/portfolio/tests/pixel-lead.test.mjs`. Команда тестов и gitignore дополнены.

Для просмотра базы локально можно открыть SQLite-клиентом только по этому пути. Она не синхронизируется с n8n HIRDA Leads и не означает отправку сообщения Артёму. Старые заявки остаются в n8n; новые подтверждённые карточкой — в SQLite.

## Следующий шаг

Локальный этап завершён; активный webhook проверен после Publish. Внешний деплой и постоянная память диалогов в этот этап не входят.

Источники реализации: официальные документы [Node SQLite](https://nodejs.org/api/sqlite.html) и [Astro environment variables](https://docs.astro.build/en/guides/environment-variables/); API проверен на локальном Node 24.21.0.
