# Pixel: диагностика серверного 502

## Реальный диагностический запрос
По отдельному разрешению пользователя выполнен ровно один POST к OpenAI Responses API существующим локальным ключом, модель gpt-4.1-mini. Input: «Привет, ответь коротко». Без инструкций Pixel, истории и личных данных; store=false, max_output_tokens=40. Результат HTTP 200, completed, ответ «Привет! Что нужно?». Значение ключа не выводилось.

Это подтверждает только работоспособность локального ключа и модели на данном запросе. Секрет опубликованного Worker этим не проверен. Корневая причина публичного 502 пока не установлена.

## Подготовлено
ApiError хранит внутреннюю диагностику этапа: сеть, таймаут, HTTP провайдера, некорректный JSON, незавершённый ответ, структура, текст или формат демосценария. Worker пишет в журнал только заранее определённый этап и числовой HTTP-статус. В ответ браузеру эти данные не добавляются. Содержимое запросов/ответов, токены, ключи и произвольный Error.message не журналируются.

Ключи, модель, Siteverify, лимиты и домены не менялись. Изменение Worker требует отдельной публикации, которая пока не выполнена.

## Проверки

- Wrangler 4.149.0 deploy --dry-run: успешная сборка Worker, без публикации.
- git diff --check: PASS.

Следующий шаг: опубликовать подготовленную диагностику в hirda-cat-api после разрешения, затем прочитать безопасный код на настоящем отказе. Успешная локальная диагностика не выдаётся за исправление публичного чата.

## Публикация диагностики
По последующему поручению пользователя Worker опубликован: 3ca25a54-c1d3-495e-a1d6-a9fa282b4846. Существующие bindings сверены с предыдущей версией и сохранены, секреты не изменялись. Запрос с допустимым Origin без токена получает 403 verification_failed. В управляемом браузере challenge не завершился в пределах ожидания; успешный публичный диалог не подтверждён, ручная отправка запрошена. Публичный отказ провайдера после новой публикации пока не зафиксирован.

## Причина подтверждена реальной отправкой пользователя
После публикации пользователь отправил сообщение из обычного браузера. Отфильтрованный журнал Worker зафиксировал только {"event":"pixel_provider_failure","stage":"provider_http","providerStatus":401}. Отказ возникает на авторизации в OpenAI после проверки Turnstile. Причина состояния удалённого ключа (отзыв/другое значение/права) не установлена; локальный ключ ранее дал 200. Запрошено отдельное разрешение заменить только OPENAI_API_KEY в действующем Worker на проверенный локальный ключ. Значения секретов не читались из Cloudflare и не выводились.

## Обновление серверного ключа
По отдельному разрешению пользователя существующий OPENAI_API_KEY заменён на ранее проверенный локальный ключ через stdin команды secret put. Перед записью сверены Worker/account и наличие имени секрета. Значение не выводилось, не сохранялось во временный файл и не добавлялось в Git. Новая действующая версия cb02f253-d996-4a49-a888-6c09fd2cbbf6 (100%), источник Secret Change. Модель, код, TURNSTILE_SECRET, лимиты и bindings сохраняются. Повторная настоящая отправка запрошена у пользователя; ответ ещё не подтверждён.

## Подтверждение пользователя и UX проверки
Пользователь подтвердил настоящий ответ публичного Pixel после обновления ключа. Последующий показанный 401 относится к Cloudflare PAT endpoint, а не OpenAI; официальная документация описывает такой ответ как ожидаемый при отсутствии PAT. На скрине видна неотмеченная галочка, а интерфейс преждевременно показывал «Думаю…».

Исправлено локально: размер Turnstile измеряется по форме, а не по пустому display:none-контейнеру; на desktop теперь flexible. Ожидание проверки и ответа разделено, есть подсказка при интерактивном challenge. Для прохождения проверки дано до 120 секунд, затем форма освобождается. Ошибка показывает безопасный код этапа, без токенов и данных диалога.

Проверено: 58 тестов, общая сборка и SEO PASS. Playwright с fixtures: desktop flexible, через 35 секунд нет ошибки/POST, после имитации success — ровно 1 POST; 320 px compact, после 121 секунды verification_wait_timeout и 0 POST, затем retry с HTTP 502 показывает http_502_upstream_unavailable. Нет overflow. Fixtures не являются настоящим проходом challenge.

Пользователь попросил убрать галочку. Предложен штатный Invisible с сохранением Siteverify/лимитов. Панель Cloudflare требует входа; пользовательский вход запрошен. Режим виджета пока не переключён. Для Invisible Cloudflare требует ссылку на Turnstile Privacy Addendum в собственной политике, учесть перед включением: https://developers.cloudflare.com/turnstile/concepts/widget/ .
