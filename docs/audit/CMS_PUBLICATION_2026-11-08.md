# My Menu — этап 2: локальная публикация и постоянный QR

Дата: 2026-11-08. Продолжение [этапа 1](CMS_RESTAURANT_WORKSPACES_2026-11-08.md). CMS работает на http://127.0.0.1:8790/.

## Реализовано

- Миграция `0004-publication.sql`: неизменяемые через API snapshots `menu_versions` и отдельный указатель `menu_publications` на выбранную версию. Старые каталоги не публикуются автоматически.
- Сохранение изменяет черновик. Публикация создаёт snapshot; дальнейшие изменения не попадают к гостям без новой публикации. Ревизия проверяется и при чтении, и внутри транзакции. При конкурентной правке отсутствующий snapshot вызывает FK-ошибку и rollback, API отвечает 409, частичной публикации нет.
- Восстановление ранее опубликованной версии не меняет черновик. Запросы publish/restore требуют owner/editor либо platform super; viewer не пишет, чужой version ID не принимается.
- Постоянный локальный URL `/m/slug/`, без параметра оформления. До первой публикации — 404. Тема хранится в settings черновика (`templateKey`), попадает в snapshot при публикации. Смена темы сохраняет URL и QR.
- QR SVG/PNG строится по серверному адресу выбранного ресторана. Адрес readonly; удалены произвольный root и отдельный выбор темы из этой формы. На localhost показано предупреждение: **такой QR недоступен с телефона и не предназначен для гостей**.
- Кнопки публикации и восстановления в существующей вкладке Vorschau, собственный диалог подтверждения и Escape. Сохранение settings требуется перед публикацией. UI переведён DE/EN/RU.
- Гостевой renderer переиспользует три текущих шаблона и общий интерактивный renderer. Встроенный JSON экранируется; скрытые блюда фильтруются адаптером. Build-time карточки скрыты до запуска renderer, чтобы не показывать случайный демокаталог. Публичное меню пока требует JavaScript, как существующие интерактивные меню.
- Worker содержит отдельные public-path handlers `/m/…/` и ограниченный whitelist статических `/menu-assets/…`. CMS API и draft preview остаются за Access/JWT и membership. Server errors не раскрывают SQL/исключения гостям.
- Локальная дополнительная миграция создаёт `menu.sqlite.pre-publication-TIMESTAMP.sqlite` перед изменением схемы; старые данные сохранены. Первичный экспорт включает snapshots и публикационный указатель.

## Проверки

- **Пройдено:** `npm test` — 107/107 во всём репозитории, 36 тестов CMS. Новые проверки: draft/published разделение, постоянство адреса при смене темы, rollback без изменения draft, запрет чужого rollback и viewer/blocked, отсутствие публичного меню до publish, HTTP assets, запрет POST гостевого меню, HTML/script injection и конфликт публикации с параллельной правкой.
- **Пройдено:** общая сборка Astro; check:public, check:seo, check:legal, check:media; cloud assets build и Worker dry-run. Это технические проверки, не проверка юридических текстов и не live deploy.
- **Пройдено Playwright на временной базе 8792:** публикация → гостевая страница с 30 карточками и загруженными фото; сохранение Pizzeria → publish по той же ссылке → возврат Street Food, при этом draft остаётся Pizzeria. QR URL совпал до и после переключения.
- **Пройдено:** собственное подтверждение rollback и Escape; QR содержит SVG; новые контролы без горизонтального overflow на 320×740, 390×844, 768×1024, 1024×768, 1920×1080, 2560×1440, 3840×2160 CSS px. Эмуляция, не физические устройства. [QR на телефоне](assets/cms-publication-qr-mobile.png), [контролы desktop](assets/cms-publication-desktop.png).
- **Пройдено:** основная локальная CMS 8790 запущена после миграции. Существующее меню осталось черновиком, автоматически не опубликовано.

## Как проверить

1. Открыть локальную CMS и выбрать ресторан.
2. Наполнить каталог, выбрать оформление во вкладке Vorschau, сохранить оформление.
3. «Entwurf veröffentlichen» → подтвердить. «Veröffentlichtes Menü öffnen» ведёт на `/m/slug/`.
4. Изменить черновик: гостевая версия сохраняет старые данные до новой публикации.
5. Выбрать старую версию и восстановить с подтверждением: guest menu меняется, draft — нет.
6. Во вкладке QR — один адрес и SVG/PNG, независимо от выбранной темы.

## Что не опубликовано и не готово

Домен не куплен, поддомены/DNS/SSL не настроены. В сети пока прежний Worker и прежняя база. **Handler перед JWT сам по себе не снимает внешнюю Cloudflare Access policy**, если она защищает Worker целиком. Перед будущим production deploy нужны backup D1, миграции 0003/0004, отдельные правила защищённого app-host и публичного меню/ресурсов, проверка внешнего email и реального гостевого доступа. Сейчас задача сознательно ограничена localhost.

Гостевые страницы сохраняют демонстрационный характер шаблонов: реальный бренд/контакты, подтверждённые составы и цены должны быть настроены перед использованием гостями кафе. Следующий этап — загрузка собственных фотографий и полноценные настройки заведения. Настоящие заказы/оплата еды не подключены; trial, Stripe, квоты и коммерческие документы ещё впереди. Маркетинговый сайт и публичное портфолио от нажатия локальной кнопки publish не меняются.
