# Pixel MVP — локальный UI, 28.10.2026

## Реализовано
- Согласованная композиция и три сценария: кафе, автосалон, домашние мастера. Локализация DE/EN/RU; единый data-модуль.
- Выбранный пример передаётся в существующий чат; общий выбор демо ограничен этими тремя сферами. Другие серверные сценарии сохранены для совместимости.
- Полный персонаж в блоке, launcher и шапке чата. Оформление и транспорт остального чата сохранены.
- Индивидуальность будущего агента клиента; почта/мессенджеры, заказы, бытовые работы и автомобильный каталог описаны как возможности подключения.
- Отдельные серверные инструкции handwerker с ограничением вопросов, безопасной передачей специалисту и черновиком без выдуманных цен/записи. Обновлён исходник знаний n8n.
- Запрошенное правило критичного обсуждения сохранено в Desktop/CODEX/AGENTS.md вне репозитория.

## Проверки
- Пройдено: npm run build --prefix apps/portfolio, 9 страниц. Существующее предупреждение о крупном Three.js chunk остаётся; это не измерение скорости.
- Пройдено: node --test apps/portfolio/tests/*.test.mjs apps/assistant-api/test.mjs — 36 тестов. Новый handwerker проверен через API с подменой upstream, без платного запроса.
- Пройдено: в Playwright все DE/EN/RU на 320, 390, 768, 1024, 1440 px без переполнения блока. Все три переключателя показывают свой диалог. Это эмуляция, не реальные устройства.
- Пройдено: CTA домашнего мастера открыл чат и отправил n8n sendMessage с названием выбранной сферы; ответ подменён тестовым, без запроса модели.
- Пройдено: Figma desktop/mobile обновлены в существующих блоках, просмотрены скриншоты. Использованы существующие компоненты сообщений и фильтров; исправлен контраст подложек. Состояние кафе статическое; интерактивные сферы доступны в коде.
- Пройдено: изображение robot-cat.webp существует, object-fit:contain сохраняет полный силуэт. В новых CTA нет декоративных стрелок.
- Не проверено: реальный ответ модели, реальная передача заказов заведению, почта/мессенджеры, оплата. Эти интеграции не создавались этим этапом.

## Публикация
Push и deploy не выполнялись. Исходник n8n-knowledge.mjs сам по себе не меняет действующий workflow; его применение нужно отдельно согласовать. Новый handwerker также требует публикации Worker перед использованием на публичном сайте. Локальная n8n-демонстрация остаётся текстовой; визуальная корзина поддерживается существующим Worker-контрактом cart/catalog.
