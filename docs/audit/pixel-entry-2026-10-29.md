# Pixel: единая точка входа и отображение проверки

## Сделано
- Кнопка первого экрана использует обычный consult-режим, как нажатие на Pixel. Удалён отдельный обработчик StudioHero; все внешние кнопки подключает существующий виджет. Демосценарии PixelExperience сохранены.
- SDK Cloudflare загружается только при отправке, а не при открытии панели.
- Штатный appearance=interaction-only убирает постоянную плашку успешной проверки; если Cloudflare потребует действие, интерактивная проверка остаётся доступной. Виджет не скрывается CSS, защита на сервере сохраняется.

## Проверено
- npm test: 56/56; общая сборка с production endpoint успешна; check:seo PASS; diff --check PASS.
- Playwright, локальная production-сборка, 390 px: кнопка первого экрана открывает consult без демосценариев и без загрузки SDK. Fixture SDK/API: 502 освобождает форму, повтор отправляет второй consult-запрос; открытие через Pixel сохраняет тот же текст приветствия. Нет горизонтального overflow.
- Desktop 1440 px, DE/EN/RU: кнопка и Pixel разделяют приветствие и черновик; открытие не загружает SDK. Отдельные кнопки демо по-прежнему меняют режим. Проверки с fixtures не доказывают реальную работу OpenAI.

## Серверная ошибка остаётся открытой
Скриншот пользователя показывает успешный Turnstile и 502 от API. Это другой этап, чем отказ проверки. Корневая причина 502 ещё не установлена. Автоматическая проверка разрешений отклонила диагностический запрос с локальным ключом и инструкциями Pixel; запрос не выполнен. Запрошено разрешение на один минимальный запрос без инструкций и личных данных. Ключи, модель и Worker не изменялись и сервер не публиковался.

Документация режима: https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/widget-configurations/ .
