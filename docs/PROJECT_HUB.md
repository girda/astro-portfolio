## Рекомендуемая организация

**GitHub Projects «HIRDA Studio»** — задачи и статусы. Представления: «Сейчас», «Все задачи», «По проектам», «Дорожная карта». Поля: Project, Status, Priority, Stage, Owner, Estimate, Links. Даты — только после оценки. На карточке различать Design / Code / QA / Published, чтобы макет не считался опубликованной функцией.

**Репозиторий/docs** — архитектура, технические решения и инструкции. После появления tracker Issues хранить в TASKS.md ссылки и крупные этапы; детальные статусы вести в одном месте. Схемы обновлять при соответствующих изменениях кода, а не обещать автоматическую синхронизацию.

**Figma** — макеты и UI kit, ссылки из задач. Не использовать Figma как единственный технический трекер.

При росте до реальных клиентов желательно приватное планирование. Приватность Project не скрывает публичные Issues или Markdown публичного repo; персональные данные клиентов хранятся отдельно с ограниченным доступом.
