# HIRDA Menu CMS — локальный первый этап

Категории → продукты для Street Food. Это локальная CMS, а не опубликованный backend.

## Запуск

Из корня репозитория, Node.js 24+:

```
npm run build
npm run cms
```

Админка: http://127.0.0.1:8790/
Предпросмотр настоящего меню: http://127.0.0.1:8790/preview/
Остановка — Ctrl+C в терминале сервера. После изменений frontend-кода повтори build; сохранение контента в CMS сборки не требует, достаточно обновить предпросмотр.

## Первая версия

- Категории: создать/изменить название, значок существующего меню, порядок и видимость.
- Продукты: создать/изменить название, категорию, описание, цену в EUR, фото из восьми существующих локальных изображений, примерные аллергены/состав, время, порядок и доступность.
- Один продукт относится к одной категории. Перенос не меняет его ID.
- Отключённая категория скрывает свои продукты в предпросмотре; отключённый продукт скрывается отдельно. Данные не удаляются.
- Физического удаления нет в первом этапе. «Все» и «Избранное» — фильтры интерфейса, не категории базы.
- Поиск в админке; защита от устаревшего сохранения из другой вкладки (revision / HTTP 409).
- Сохранение в SQLite и повторное открытие после перезапуска.
- Предпросмотр использует реальную собранную страницу Street Food, её карточки, фильтры, диалоги, анимации и демонстрационную корзину.

## Где данные

`apps/menu-cms/.local-data/menu.sqlite` и её WAL-файлы игнорируются Git. Начальное заполнение один раз из `apps/streetfood/src/data/catalogue.json`: шесть категорий и 24 продукта. Перезапуск не сбрасывает правки и не импортирует исходный JSON заново.

Исходный JSON остаётся источником публичной статической сборки. SQLite — отдельный локальный черновик. В этой версии нет кнопки публикации или автоматической синхронизации SQLite → GitHub Pages. База, админка и тестовые изменения не входят в публичную сборку. Локальные заявки Pixel/n8n не затрагиваются.

Без удаления файла базы: резервную копию делай после остановки CMS. Самостоятельно не удаляй SQLite ради обновления кода.

## Границы безопасности

Сервер слушает только 127.0.0.1. Проверяются Host, Origin, Sec-Fetch-Site, content-type, размер JSON, revision и поля. Запросы к БД параметризованы; foreign key связывает продукты с категориями. CMS не отправляет контент внешним сервисам и не содержит API-ключей. Админка выводит пользовательские значения через textContent; JSON предпросмотра экранирует `<`.

Это доверенная локальная среда без учётных записей. Не выставляй этот сервер через туннель, reverse proxy или публичный интерфейс. Для сетевой CMS отдельно нужны авторизация, роли, резервное копирование, развёртывание и проверка безопасности. Собственная клиентская машина и её локальные приложения остаются доверенной границей.

Загрузка новых фотографий, мультиязычный контент, редактирование extras, массовые операции, публикация, реальные заказы и платежи в этот этап не входят. Рецептуры, цены и аллергены остаются демонстрационными до подтверждения заведением.

## Проверки

`npm test` в корне включает контракт каталога, SQLite и HTTP API. `npm run build` проверяет интеграцию со статическим меню. Браузерная проверка — отдельный отчёт в docs/audit.

- После создания категории она выбирается сразу. После сохранения/переноса продукта открывается его категория, поиск и фильтр сбрасываются, чтобы результат не оказался скрыт.
- Фото подписаны понятными названиями вместо имён файлов.
- Закрытие редактора или уход со страницы с несохранёнными изменениями вызывает предупреждение. Во время сохранения повторные действия блокируются.
- При HTTP 409 кнопка «Обновить данные, сохранив черновик» загружает актуальную версию. Независимые изменения объединяются; пересекающиеся поля перечисляются, и пользователь проверяет свои значения перед явным сохранением. Автоматической перезаписи базы нет.
- Сетевая ошибка не выдаётся за успешное сохранение; кнопки снова доступны для повторной попытки. Запрос ограничен 12 секундами.

Экспорт/публикация и загрузка новых фото в этот этап не добавлены.

## Компактная CMS и история · 02.11.2026

По новому референсу HubSpot дизайн заменён: тёмная навигация, белые рабочие панели, бирюзовый акцент, плотный список и редактор справа. На телефоне — нижняя навигация, горизонтальные категории, полноэкранный редактор с закреплённым сохранением. Прежнее описание Material 3 выше — история этапа.

Раздел «История» показывает успешные создания/правки, дату, версию, поля «Было / Стало». Журнал хранится в той же SQLite и пишется одной транзакцией с контентом. Старые изменения не восстанавливаются задним числом. Автор обозначен как локальная CMS: отдельных пользователей пока нет. Просмотр порциями по 30 записей; API GET /api/history принимает limit (1–50) и before (версия). Откат версий не реализован.

Таблица history добавляется автоматически без пересева данных. Перед обновлением рабочей базы сохранена приватная копия .local-data/before-history-2026-11-02.sqlite; все .local-data игнорируются Git. Перезапуск сервера нужен для нового API, сейчас рабочий сервер уже перезапущен.

## Сетевая CMS (Cloudflare)

Worker: `hirda-menu-cms`; D1: `hirda-menu-cms` (WEUR).
Адрес: https://hirda-menu-cms.hirda-assistant-api.workers.dev

Код опубликован, первоначальные данные перенесены. Вход ещё не настроен: сервер
намеренно возвращает 403 для всех запросов, пока нет конфигурации Access.
Локальная SQLite остаётся отдельной базой; автоматической двусторонней синхронизации нет.
Сохранение в CMS изменяет черновик и предпросмотр, а не публичное меню GitHub Pages.

### Завершение настройки входа

1. Создать self-hosted приложение Cloudflare Access для точного hostname Worker.
2. Политика Allow: Include → Login Methods → One-time PIN. Это допускает подтверждённый email только к регистрации; права на каталог проверяет CMS в D1. Не использовать Bypass.
3. Включить email One-time PIN как способ входа. Новые пользователи получают pending/viewer; доступ выдаёт супер-админ.
4. В `cloud/wrangler.jsonc` добавить `vars`: `ACCESS_TEAM_DOMAIN` (домен команды
   `*.cloudflareaccess.com`, без протокола), `ACCESS_AUD` (Application Audience),
   `ADMIN_EMAIL` (единственный разрешённый адрес).
5. Повторить deploy. Проверить вход владельца, отказ без входа, сохранение и историю.
   Worker проверяет подпись JWT, issuer, audience, expiry и подтверждённый email; затем читает текущую роль и статус из D1.

Команды из `apps/menu-cms`:

```sh
npm ci
npm test
# Сначала собрать Street Food через корневой npm run build.
node cloud/build.mjs
../assistant-api/node_modules/.bin/wrangler deploy --config cloud/wrangler.jsonc --dry-run
../assistant-api/node_modules/.bin/wrangler deploy --config cloud/wrangler.jsonc
```

`cloud/export-local.mjs` экспортирует согласованный снимок SQLite в игнорируемый
`.local-data/cloud-import.sql`. Это инструмент первоначального переноса, **не регулярная
синхронизация**. Не запускать импорт поверх действующей сетевой базы: первичный ключ
защищает от перезаписи, но новый перенос требует отдельного плана.

Изменение каталога и событие истории входят в одну D1 batch-транзакцию. Уникальный
номер ревизии запрещает двум параллельным запросам сохранить одну исходную версию.
В случае конфликта клиент получает 409 и сохраняет черновик для повторной проверки.

Новые фотографии 06.11.2026: 24 изображения, по одному на продукт. Исходники созданы
native ImageGen; WebP оптимизированы до 1000 px. Реестр происхождения и контрольные
суммы находятся в `docs/MEDIA_PROVENANCE_2026-10-30.json`.

### Пользователи

- Миграция `cloud/migrations/0002-users.sql` добавляет учётные записи и аудит изменения доступа.
- В сетевой D1 создан владелец Artem Hirda (`artem.girda@gmail.com`), super_admin/active.
- Открытая регистрация: подтверждение email через Access → заполнение имени → ожидание одобрения.
- viewer: каталог/история/предпросмотр; editor: дополнительно изменение контента;
  super_admin: дополнительно `/users.html`, одобрение, блокировка, роли.
- `/account.html`: собственное имя, email, статус, выход. Клиент не может назначить себе роль.
- В таблице пользователей показываются имя, email, роль, статус, дата регистрации и последний вход.
- Владелец защищён от блокировки/понижения; пользователь не меняет собственный доступ.
- Паролей в D1 нет. История контента записывает ID и имя автора новых изменений.
- Блокировка применяется сервером при следующем запросе, независимо от состояния интерфейса.
- Полноценный вход по email остаётся непроверенным до настройки Access.


## Оформление Diner и состав блюд (08.11.2026)

Во вкладке «Предпросмотр» редактируются заголовок (до 80 символов), подзаголовок,
растровый логотип PNG/JPEG/WebP и режим Diner. Логотип вписывается пропорционально;
клиент уменьшает его до 700×240 и сохраняет как небольшой WebP в настройках каталога.
PUT `/api/settings` использует ту же проверку версии, историю и права записи, что продукты.

В редакторе продукта — 14 аллергенов, отдельное подтверждение владельцем и до шести
вариантов порции с ценами. Старые текстовые сведения сохраняются; начальные отметки
переносятся только из явно записанных названий аллергенов. Они НЕ подтверждены автоматически.
Для настоящего кафе владелец обязан проверить состав; фотография не источник аллергенов.

По умолчанию Diner информационный: без избранного, добавления и корзины. Варианты цен
отображаются в этом режиме. Демонстрационный режим заказа использует основную цену;
выбор варианта в заказе и отправка заказа на кухню ещё не подключены.
Сохранение локальной CMS не публикует данные на GitHub Pages или в D1.

## QR-меню (08.11.2026)

Вкладка «QR-меню»: выбрать Street Food / Diner / Pizzeria, указать базовый HTTPS-адрес
и нажать «Создать QR». Итоговая ссылка показана под кодом; доступны SVG и PNG.
Код создаётся в браузере библиотекой qrcode-generator 2.0.4 (MIT), без внешнего QR API.
Настройки QR сохраняются только в этом браузере, не в D1 и не в каталоге.
Это не подключение DNS/домена: указанный сайт должен уже работать по нужному адресу.

Локальный сервер отдаёт `/qr-generator.mjs` из закреплённой npm-зависимости;
cloud/build.mjs копирует её в защищённые assets. Уведомление MIT:
public/qr-generator-LICENSE.txt. Документация библиотеки:
https://github.com/kazuhikoarase/qrcode-generator/tree/master/js.

Для проверки скачан PNG, распознан BarcodeDetector в Chromium; декодированная ссылка
совпала с выбранным адресом. Проверка физической камерой телефона не выполнялась.
