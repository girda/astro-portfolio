# HIRDA Menu CMS — локальный первый этап

Категории → продукты для Street Food. Это локальная CMS, а не опубликованный backend.

## Запуск

Из корня репозитория, Node.js 24+:

```
npm run build
npm run cms
```

Админка: http://127.0.0.1:8790/
Предпросмотр настоящего меню: http://127.0.0.1:8790/preview/
Остановка — Ctrl+C в терминале сервера. После изменений frontend-кода повтори build; сохранение контента в CMS сборки не требует, достаточно обновить предпросмотр.

## Первая версия

- Категории: создать/изменить название, значок существующего меню, порядок и видимость.
- Продукты: создать/изменить название, категорию, описание, цену в EUR, фото из восьми существующих локальных изображений, примерные аллергены/состав, время, порядок и доступность.
- Один продукт относится к одной категории. Перенос не меняет его ID.
- Отключённая категория скрывает свои продукты в предпросмотре; отключённый продукт скрывается отдельно. Данные не удаляются.
- Физического удаления нет в первом этапе. «Все» и «Избранное» — фильтры интерфейса, не категории базы.
- Поиск в админке; защита от устаревшего сохранения из другой вкладки (revision / HTTP 409).
- Сохранение в SQLite и повторное открытие после перезапуска.
- Предпросмотр использует реальную собранную страницу Street Food, её карточки, фильтры, диалоги, анимации и демонстрационную корзину.

## Где данные

`apps/menu-cms/.local-data/menu.sqlite` и её WAL-файлы игнорируются Git. Начальное заполнение один раз из `apps/streetfood/src/data/catalogue.json`: шесть категорий и 24 продукта. Перезапуск не сбрасывает правки и не импортирует исходный JSON заново.

Исходный JSON остаётся источником публичной статической сборки. SQLite — отдельный локальный черновик. В этой версии нет кнопки публикации или автоматической синхронизации SQLite → GitHub Pages. База, админка и тестовые изменения не входят в публичную сборку. Локальные заявки Pixel/n8n не затрагиваются.

Без удаления файла базы: резервную копию делай после остановки CMS. Самостоятельно не удаляй SQLite ради обновления кода.

## Границы безопасности

Сервер слушает только 127.0.0.1. Проверяются Host, Origin, Sec-Fetch-Site, content-type, размер JSON, revision и поля. Запросы к БД параметризованы; foreign key связывает продукты с категориями. CMS не отправляет контент внешним сервисам и не содержит API-ключей. Админка выводит пользовательские значения через textContent; JSON предпросмотра экранирует `<`.

Это доверенная локальная среда без учётных записей. Не выставляй этот сервер через туннель, reverse proxy или публичный интерфейс. Для сетевой CMS отдельно нужны авторизация, роли, резервное копирование, развёртывание и проверка безопасности. Собственная клиентская машина и её локальные приложения остаются доверенной границей.

Загрузка новых фотографий, мультиязычный контент, редактирование extras, массовые операции, публикация, реальные заказы и платежи в этот этап не входят. Рецептуры, цены и аллергены остаются демонстрационными до подтверждения заведением.

## Проверки

`npm test` в корне включает контракт каталога, SQLite и HTTP API. `npm run build` проверяет интеграцию со статическим меню. Браузерная проверка — отдельный отчёт в docs/audit.
