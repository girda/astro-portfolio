# Pixel и локальный n8n

## Где находится действующий интерфейс

`src/components/AIAssistantWidget.astro` подключается из `PortfolioPage.astro`.
Корневой `hirda-ai-widget/` — старый комплект установки, приложение его не импортирует.
Стили, разметка, эмоции кота, адаптивность и управление фокусом не изменялись.

## Запуск

1. Запусти n8n и открой workflow с Chat Trigger → AI Agent.
2. В Chat Trigger используй Embedded Chat и скопируй его Chat URL.
3. Создай или дополни **apps/portfolio/.env.local**:

   ```dotenv
   PUBLIC_N8N_CHAT_URL=http://localhost:5678/webhook/ТВОЙ-ID/chat
   ```

   Используй реальный URL из n8n. Для `/webhook-test/…` включи прослушивание тестовых событий;
   для `/webhook/…` workflow должен быть активен. Имя production webhook в n8n не означает публикацию портфолио.

4. В Allowed Origin (CORS) разреши origin локального Astro, например `http://localhost:4321`.
   При другом порте или `127.0.0.1` укажи фактический origin. Не обходи CORS через `no-cors`.
5. Для ответа выбери When Last Node Finishes / Return the last node output
   (название зависит от версии n8n). Ожидается JSON `{ "output": "Ответ" }` либо `[{ "output": "Ответ" }]`.
   Потоковый ответ в этой интеграции не используется.
6. Для памяти подключи одну и ту же memory-ноду к Chat Trigger и AI Agent;
   в AI Agent/Memory используй Session ID из Chat Trigger (`sessionId`). Сам sessionId не включает память автоматически.
7. Из `apps/portfolio` запусти `npm run dev -- --background --port 4321`.
   Если сервер уже работает, после изменения env перезапусти его. Состояние: `npm run astro -- dev status`.
8. Открой сайт по адресу Astro, нажми на Pixel, отправь сообщение и проверь Execution в n8n.

## Что отправляется

```json
{ "action": "sendMessage", "sessionId": "UUID", "chatInput": "Сообщение посетителя" }
```

`sessionId` создаётся через `crypto.randomUUID()` и хранится в sessionStorage.
Консультация и демо имеют разные ID, как и отдельные истории в интерфейсе.
Повторное открытие и перезагрузка в той же вкладке сохраняют ID; выбор нового демо сбрасывает демо-сессию.
Сообщения интерфейса после перезагрузки не восстанавливаются: это поведение оставлено прежним,
но n8n с правильно настроенной памятью продолжает помнить контекст сессии.
Если браузер запрещает хранилище, чат работает с ID в памяти до перезагрузки.

## Получение ответа и ошибки

Транспорт находится в `src/scripts/pixel-n8n.ts`.
Он читает поле `output` и возвращает существующему UI `{ text }`.
Ожидание, повторная попытка, защита `busy` и активное поле ввода уже были в Pixel и сохранены.
Таймаут n8n — 60 секунд. Сетевая ошибка, неверный JSON/пустой output и HTTP-ошибки
показываются через существующее сообщение ошибки; HTTP 429 — через сообщение о лимите.
Новый запрос во время ожидания не отправляется, появляется прежняя подсказка дождаться Pixel.

Корзина, быстрые варианты и структурированные демо-данные зависят от ответа backend.
Обычный `output` n8n — текстовый ответ; эта интеграция не добавляет workflow товаров/заказов
и не переписывает существующие демо-сценарии.

## Публичная версия

n8n выбирается **только при `import.meta.env.DEV` и заполненном `PUBLIC_N8N_CHAT_URL`**.
Production build / preview / GitHub Pages используют прежний `PUBLIC_ASSISTANT_API_URL`
и Turnstile; без публичного API остаются прежние локальные демо-ответы.
Без n8n URL локальная разработка также сохраняет прежний API на порту 8787.
Не меняй публичный API на localhost. В GitHub Actions переменная n8n не нужна.

`PUBLIC_` означает, что URL виден браузеру в dev. OpenAI key, n8n API key и другие
секреты остаются в n8n Credentials / на backend и не добавляются в этот файл.
`.env.local` игнорируется Git; не добавляй его через `git add -f`.

## Проверки

Из `apps/portfolio`, Node 24:

```bash
node --test tests/pixel-n8n.test.mjs
npm run build
git check-ignore -v .env.local
```

Проверки транспорта используют подставной fetch и не вызывают OpenAI.
В браузере проверь: ответ, второй вопрос с тем же sessionId, перезагрузку,
повторный Enter во время ответа, ошибку сети и повторную попытку без дубликата сообщения.
