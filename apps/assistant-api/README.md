# HIRDA CAT — локальный API

Node.js 24+, без дополнительных зависимостей. Сервер слушает только 127.0.0.1.

1. Скопируй `.env.example` в `.env` в этой папке.
2. Вставь свой ключ после `OPENAI_API_KEY=` в `.env`. Не присылай ключ в чат.
3. Из корня astro-portfolio: `npm run dev --prefix apps/assistant-api`.
4. Открой портфолио на http://localhost:4321 и чат кота. Dev-версия автоматически обращается к порту 8787.

После изменения .env перезапусти API. Если меняешь PORT, измени также локальный apiUrl в AIAssistantWidget.astro.
Проверка: `npm test --prefix apps/assistant-api` (моки, без ключа и расходов).

## Данные и поведение

- Общий прайс: apps/portfolio/src/data/pricing.json. Его читают страница и backend.
- Проекты и контакт: существующие projects.ts и contact.ts.
- Правила консультации: knowledge.mjs. Новые подтверждённые сведения добавляй туда.
- До 5 последних пар сообщений находятся в памяти вкладки, без localStorage и базы.
- Пользовательский текст и история передаются в OpenAI. В запросе store:false; это не обещание нулевого хранения у провайдера.
- Ответы вставляются через textContent, без исполнения HTML. Никаких внешних действий агент не выполняет.
- Сервер не пишет сообщения и ключи в логи. Лимиты: 20 запросов/мин на локальный сервер, 2 одновременно, 24 KB тело, до 600 выходных токенов.
- Модель настраивается OPENAI_MODEL. По умолчанию gpt-4.1-mini. Доступ к модели и биллинг проверяются реальным запросом.

## Перед публикацией

Это локальная интеграция, не готовый публичный endpoint. Production-сборка сайта сохраняет деморежим. GitHub Pages не исполняет этот backend.
Для публикации отдельно выбираем хостинг, HTTPS, серверный секрет, реальные домены, устойчивые лимиты расходов/запросов и защиту от автоматических обращений. CORS не заменяет такую защиту. Также согласуем уведомление о передаче сообщений и политику обработки данных. Не открывай этот dev-сервер наружу через туннель.
